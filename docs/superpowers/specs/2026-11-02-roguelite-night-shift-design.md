# 随机夜班 · 轻量肉鸽模式设计

## 意图

在 04「黎明之前」加入可重复游玩的随机夜班。玩家扮演布莱切利园夜班小组成员，每局选择行动路线、处理短事件、收集有限工具，最后用真实 Enigma 运算核验一条截报并作出交接决定。单局目标约 10 分钟，重点是轻松重玩、路线选择和不同岗位体验，不扩写现有固定主线。

## 目标

- 从 04 的主线简报页进入「随机夜班」，结束或退出后能回到原主线且不丢主线状态。
- 每局 4 层分支路线、4 个现场事件和 1 个最终核验；单局实测中位数目标 9–11 分钟，允许随时暂停，不设现实倒计时。
- 每局由可复现 seed 决定案件、节点顺序、事件选项和奖励；同 seed 必须得到相同案件与路线。
- 玩家选择 3 种岗位之一：截收员（开局获得频道线索）、档案助理（预览下一层并一次重抽路线）、机修学徒（一次免除设置操作的错误代价）。能力各用一次，不叠永久数值。
- 事件从截收、档案、分析、接线/设置、同事求助、茶歇工具中抽取。选择改变线索、当班余裕或最终难度。
- 真实密码生成和验证必须调用 `src/cipher.js`；案件单明示转子顺序 I–II–III、环位 AAA、左/中轮位和唯一一对接线，玩家只推断未知右轮起始字母。生成时穷举该条件下 26 个右轮字母，验证密文可解、crib 对齐无矛盾且恰有一个候选。不得把虚构的候选反馈说成真实 Bombe 行为。
- 当班余裕从 3 开始；错误猜测或高风险选择可消耗余裕。余裕耗尽不锁死流程：提供现场提示并允许完成，但结局档案标记证据不完整。
- 最终核验包括设置候选、解出短报、选择谨慎交接。结局按证据链与交接判断给出完整、带疑点或待复核三种档案，不以失败清空已解锁内容。
- 解锁只增加新岗位外观、案件变体和事件条目，不提供永久数值优势。

## 非目标

- 不改写或替换 04「黎明之前」现有 15 节拍固定主线，不把肉鸽随机事件混入主线证据链。
- 不做战斗、敌人、永久属性成长、装备刷取、实时倒计时或强制每日任务。
- 不新增完整 3D 场景、不复制第三方完整游戏，也不引入独立游戏引擎。
- 不宣称玩法复现完整历史 Bombe 搜索；每局是受史实约束的教学演练。

## 单局流程与节奏

| 环节 | 目标时长 | 玩家动作 |
|---|---:|---|
| 接班与岗位 | 0:30–0:45 | 看案件简报，选岗位与一项随身工具 |
| 第一层：截收 | 1:00–1:20 | 从频道或信号记录中确认目标报文 |
| 第二层：档案 | 1:00–1:20 | 在两个档案/同事节点中选一路，获得 crib 或补给 |
| 第三层：分析 | 1:20–1:40 | 对齐 crib、辨认自映射冲突或建立字母关系 |
| 第四层：机房 | 1:20–1:40 | 调整简化设置、检查候选或换取最后一条提示 |
| 最终核验与交接 | 2:00–2:30 | 用候选设置解密短报，判断并封存交接 |
| 行间镜头与复盘 | 0:45–1:00 | 查看收集到的证据和本局记录 |

场景时间随完成事件推进，用于氛围显示，不等同于现实计时。读档、动画、无障碍停顿和暂停不消耗资源。

## 肉鸽循环

1. 生成 seed、案件模板、岗位选择和 4 层路线图。每层展示两条可读路线，节点类型和奖励清晰可见；档案助理可使用一次路线重抽。
2. 玩家每层选择一个节点。节点有短场景文本、一个可操作选择、即时反馈和一条证据/补给结果；单个节点只允许一次主要交互，减少重复点击。
3. 证据分为报文来源、密码约束、完整解密三类。路线可以提供不同证据，但路线生成器保证至少存在一条能收集完整核验所需线索的路径。
4. 工具为一次性：放大镜展开一级提示、备用纸带重做一次设置、茶水恢复 1 点当班余裕；同局最多持有 2 件，第三件必须使用、替换或放弃。
5. 最终台让玩家提交一个右轮起始字母；系统用实际 Enigma 引擎检查 crib 并逐字解密短报。最多 3 次未命中；之后自动开放强提示，但仍由玩家提交最终设置与交接判断。
6. 结算保存 seed、岗位、路线、证据、失误和结尾；玩家可以复制 seed 重开同局或抽取新局。

案件首发采用 6 个经过算法验证的模板，随机改变已知左/中轮位、右轮答案、单对 plugboard 设置、crib 位置和短明文词条；所有已知设置在案件单公开，右轮字母是唯一未知量。生成器只在 26 个右轮候选中检查 crib，目标必须唯一；不唯一就重抽模板参数，达到重试上限时使用对应模板的预验证案件，不把坏局交给玩家。

## UI 与交互

- 入口位于 04 主线简报中的次级动作「随机夜班」；主线继续使用原来的开始按钮。
- 开始面板选岗位和案件档案；运行时沿用 04 的 Three.js 现场、相机分区与暖铜/纸白/墨绿材质。右侧现场记录显示当前事件，证据与工具放在紧凑的页脚/侧栏，不堆叠多层卡片。
- 路线图是四层节点路径，当前层与可选节点清晰；已走节点显示结果，未走节点不展示隐藏内容。
- 主操作使用按钮、字母键盘/实体键盘均可完成；键盘方向/Tab/Enter 有焦点状态，点击目标至少 44px。
- 事件切换使用短的相机移动和内容淡入；支持减少动态效果、跳过转场和暂停。隐藏标签页自动暂停。
- 手机端先显示场景标题与任务，再显示当前可操作区；路线图可折叠查看，工具与证据不会挤压主操作。
- 继承项目现有档案展陈视觉，不新增字体或远程素材；颜色不单独承担证据状态表达。

## 技术与参考

- 项目技术为原生 ES modules、Three.js、Node test runner、esbuild；沿用 `src/challenge-engine.js` 的 `seededRandom`、`shuffle` 和 `src/cipher.js`。
- 已确认 GitHub `ondras/rot.js` 仓库可访问（检查时 HEAD `46782e248c2db9d379a5e4f13bb8323f18dff04b`）。它面向网格 Roguelike；本模式采用已有展馆房间的分支路线，不引入该工具库或第三方完整游戏代码。
- 新增的随机数据使用纯函数；DOM 生命周期和现场交互独立；CSS 以 `rogue-` 前缀隔离。
- 浏览器本地保存最多 20 条已完成档案；损坏或版本过期的存档忽略并允许继续开新局。

## 验收

- 同 seed 产出完全一致的案件、路线、奖励和结尾；不同 seed 的路线或案件至少一项变化。
- 每个案件模板和生成参数均由 `cipher.js` 真实加解密；唯一解搜索域严格限定为右轮 A–Z，自动验证目标唯一、crib 无自映射冲突、无不可完成路径。
- 任一岗位、路线和余裕状态都能到达结算；余裕耗尽只改变提示与档案评价，不造成软锁。
- 主线状态在进入、暂停、退出、重新进入随机模式后保持不变；运行中的页面离开/销毁会移除监听器和暂停动画。
- 桌面与 390px 手机无横向溢出；完整流程可用键盘和触摸完成；WebGL 失败时保留文本事件和密码核验。
- 浏览器真人试玩中位数 9–11 分钟；若首轮超出 8–12 分钟，优先压缩阅读和跨区转场，不删案件推理步骤。
- `npm test`、`npm run build`、`git diff --check` 通过；截图覆盖简报、路线、设置核验、结算桌面和手机视口。
