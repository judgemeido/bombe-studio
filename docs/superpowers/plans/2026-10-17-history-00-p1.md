# 00 战时序章 P1 视觉样稿 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 提供可独立打开的首屏＋图灵人物段 HTML 视觉样稿，供用户在桌面和手机上确认视觉方向。

**Architecture:** 单独的 `history-preview.html` 使用语义 HTML、局部 CSS 和轻量原生模块，不导入主应用或 Three.js。沿用现有 esbuild 和开发服务，只增补样稿入口及静态资源支持，不改首页或 hash 路由。获用户确认后再规划 P2–P4。

**Tech Stack:** 原生 HTML/CSS/JavaScript；esbuild；node:test + happy-dom；真实浏览器验收。不新增 npm 依赖。

**Spec:** [体验方案](../../HISTORY_00_SPEC.md)、[文案](../../HISTORY_00_COPY.md)、[来源登记](../../HISTORY_00_SOURCES.md)。P0 已于 2026-10-17 获用户确认；本文仅覆盖 P1，不把确认扩大为完整上线授权。

## Global Constraints

- 深海蓝 `#142633`、档案灰白 `#E4E7E2`、机械绿 `#52614D`、黄铜 `#B69A67`；普通正文对比度至少 4.5:1。
- 保持现有浏览器目标 chrome110 / firefox110 / safari16；不迁移框架、不引入大型动画库。
- 静态 HTML 初始可读；不伪造百分比、不强制等待、不全屏阻挡跳过入口。
- 不改 `src/navigation.js`、`src/main.js`、`index.html` 或解密/挑战代码；首页仍为原应用，样稿独立访问。
- 未获准肖像不得使用；图灵区明确标注「肖像素材待定」，不能冒充完成的图文版本。
- 不自动播放声音，不劫持滚动；reduced-motion 下关闭位移动画。

## Review Focus

1. 图片 decode 拒绝或永不结束：3 秒内解除等待，正文与跳过链接始终可用。（Task 2）
2. 页面已离开后图片晚到：不得再次改 DOM、抢焦点或重启动画。（Task 2）
3. 无 JS / 无 IntersectionObserver / reduced-motion：两段正文完整可读。（Task 2、3）
4. 静态服务扩展白名单：合法资源可访问，编码后的目录穿越与隐藏文件仍被拒绝。（Task 1）
5. 390px 窄屏与键盘：无横向溢出、不裁切标题、焦点可见、图灵年表可展开。（Task 3）

## Task 1：独立静态样稿与影像依据

**接口：** 独立页面地址 `/history-preview.html`；主按钮链接 `/#/`，次级阅读链接 `#turing`。`build.mjs` 增加 `historyPreview: 'src/history-preview.js'` 入口。开发页脚本引用 `dist/historyPreview.js`，构建复制 HTML 时仅改为 `historyPreview.js`。CSS 及 `assets/history` 在构建后保持相同相对位置。

- [ ] 先补测试：读取 HTML 到 happy-dom，断言首屏正式标题、图灵姓名、人物正文、`#turing`、`/#/` 与「视觉样稿」标记存在；源码不引用 `dist/app.js`，正文不靠脚本注入。执行 `node --test tests/history-preview.test.mjs`，确认因页面缺失而失败。
- [ ] 复核 A1 的 NHHC 原档案与 Commons 许可；一致时下载到 `assets/history/atlantic-aquila-1941.jpg`，登记许可、档案号、文件名与裁切。若原站不可用，不能冒称交叉核对完成；可用明确标注的原创海洋示意图继续构图，保留影像未决项。A2 仅在授权链解决后落盘，否则使用明确标注素材待定的编辑版面，不生成假肖像。
- [ ] 创建两段静态 HTML：首屏沿用已确认标题，图灵段沿用 COPY 的人物主文与可展开年表。采用不对称影像窗和大号章节索引，避免重复卡片；样稿只展示这两段，明确省略的中间场景。
- [ ] 为开发服务仅加入明确的 HTML/CSS 资源和 `assets/history` 目录；保留 realpath、路径包含性、隐藏路径与扩展名限制。JPEG/WebP 补正确 MIME。构建复制已采用资源与许可说明。
- [ ] 测试通过并执行 `npm run build`。启动开发服务后检查样稿、CSS、JS、本地图片为 200；编码目录穿越、隐藏文件和其他 assets 子目录为 403/404；生产输出 HTML 的所有本地链接均能解析。记录请求结果。
- [ ] 提交独立页面与资源支持，提交信息：`feat: 新增战时序章独立视觉样稿骨架`。

## Task 2：真实载入状态和渐进增强

**接口：** `createHistoryPreview(root, { image, motion, timeoutMs = 3000 }) -> { destroy() }`，位于 `src/history-preview.js`。`image` 为首屏 HTMLImageElement（缺图时可为 null），`motion` 为 MediaQueryList。root 的 `data-load-state` 为 `loading | ready | fallback`，状态文字位于 `[data-load-status]`。模块只在样稿根存在时自动挂载，pagehide 调用 destroy。

- [ ] 先写失败测试：注入可控制的 image.decode promise；验证 resolve→ready，reject→fallback，超时→fallback，null→fallback。采用测试 mock timer 验证 3000ms 边界，不真实等待三秒。断言正文及跳过链接从未被隐藏。
- [ ] 再写生命周期测试：destroy 后 resolve/reject、超时均不再改状态；重复 destroy 不抛异常；decode 缺失时监听 load/error 并检查 complete/naturalWidth。reduced-motion 不创建位移动画；无观察器时直接保留全部内容可见。
- [ ] 实现控制器：仅等待首屏图，不等待字体或 3D；加载区是小型扫描索引，不是遮屏；aria-live polite 仅播报状态变化。超时后不让晚到回调覆盖 fallback，destroy 清理计时器、监听与观察器。
- [ ] CSS 默认可见，动效仅增强海洋线条、索引和局部揭示；不通过把整段文字设为透明来实现入场。移动端不使用 sticky；reduced-motion 禁用扫描位移、视差与平滑滚动。
- [ ] 执行 `node --test tests/history-preview.test.mjs`，确认新增测试全部通过；提交：`feat: 为序章样稿加入可降级载入与滚动增强`。

## Task 3：桌面/手机视觉校准与回归

- [ ] 在真实浏览器检查 1440×900 与 390×844：首屏、图灵段各截图；检查 `scrollWidth <= clientWidth`，标题不截断、正文不挤压、图注可读。照片若只有 1200px，不拉伸成全屏超清背景。
- [ ] 验证锚点、年表展开、键盘 Tab 与可见焦点、主按钮进入旧 `/#/`；无 JS 场景直接读 HTML。检查 reduced-motion 和图片请求失败场景，确认状态回退且正文可读。记录实际检查结果，不以截图代替交互验收。
- [ ] 检查首屏/人物段正文、按钮与图注对比度；根据实际结果微调 CSS，不更换已确认艺术方向。检查没有主应用与 Three 的脚本请求。
- [ ] 执行 `npm test`、`npm run build`、`git diff --check`，保存截图至 `output/history-00-p1/`；编写 `docs/HISTORY_00_P1_QA.md`，明确真实图片覆盖与未决肖像许可，不把 P1 写成完整 00 页面上线。
- [ ] 提交：`style: 校准序章双端视觉并记录P1验收`。提供预览地址和四张关键截图，请用户审阅后才进入 P2–P4。

## 计划自检

P1 范围覆盖：两段样稿、桌面手机、载入状态、渐进增强、可跳过、无障碍、素材署名与既有应用隔离。完整七幕、首页路由及 WebGL 延迟初始化属于后续阶段，故本计划不执行；S6 仍须在七幕发布前补核。本计划不要求新框架或额外依赖，各接口仅服务样稿。
