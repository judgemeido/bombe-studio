## 3. 从两个 GoodProject 得出的可迁移原则

### 3.1 参考 `rhine-lock` 的前端组织方式

研究重点：`frontend/src/App.svelte`、`frontend/src/lib/lock.svelte.ts`、`frontend/src/lib/transition.ts`、`frontend/src/lib/audio.ts`、`frontend/src/lib/ui/*`、`CONTRACT.md`。

迁移到 Bombe 的做法：

- **单一状态边界**：页面、模型、任务、音频、动效和弹层都由统一状态对象驱动；Three.js 场景只读取状态并发出事实事件，不直接修改学习结果。
- **事件契约**：统一使用 `page:enter`、`page:leave`、`model:select`、`model:explode`、`experiment:step`、`challenge:answer`、`mission:advance`、`motion:change`、`quality:change` 等事件。
- **可逆转场**：进入、退出、快速跳过和中途打断都从当前进度继续，不通过删除并重建 DOM 解决动画冲突。
- **界面与业务分层**：内容、页面状态、Three.js、转场、音频和资源释放分别拥有明确职责，避免某个按钮同时修改模型、路由和题目状态。
- **错误与降级可用**：WebGL、音频或资源失败时仍保留文字、时间线、题目判定和返回入口。
- **键盘焦点闭环**：弹层打开后焦点进入弹层，关闭后返回触发按钮；输入、Tab、Esc、Enter 和减少动效状态都要有确定行为。
- **短促反馈音效**：进入、选择、拆解、错误、完成使用不同声音；声音无法播放时不阻塞页面。

明确不迁移：Wayland/GTK/PAM/桌面锁定协议、Svelte 运行时、锁屏品牌和系统权限逻辑。

### 3.2 参考 `RhineLabUI` 的 Three.js 组织方式

研究重点：`src/model-viewer.ts`、`src/viewer-camera.ts`、`src/instance-updates.ts`、`src/three-resources.ts`、`src/render-quality.ts`、`src/quality-settings.ts`、`src/motion-preferences.ts` 及 `verification/*`。

迁移到 Bombe 的做法：

- **查看器生命周期**：每个页面的 Three.js 场景提供 `load`、`resize`、`update`、`setQuality`、`setMotion`、`dispose`，离开页面后释放几何、材质、纹理、后处理、实例缓冲和监听器。
- **相机缓动**：记录球面角度、目标、距离和焦点；复位使用最短角度路径和连续插值；减少动效时直接到位。
- **拆解单一进度源**：模型位置、热点、标题和说明均从同一拆解进度计算；中途反向沿原路径返回，不创建第二套临时位置。
- **实例化重复物体**：相同鼓轮、灯、标记和环境部件使用 `InstancedMesh`；需要独立拾取、标注或拆解的对象保持稳定 ID 和独立对象。
- **质量分档**：高质量、标准、性能优先三档；低质量减少阴影、AO、后处理和粒子密度，但不删除教学信息。
- **静止帧复用**：页面暂停、弹层打开、后台标签页和待机状态时降低或停止无意义的渲染。
- **验证证据**：按页面、视口、画质、动效和资源释放分别生成检查结果，而不是只记录一次“构建成功”。

明确不迁移：Rhine Lab 的品牌、内容、模型、音乐、壁纸资源和整套页面视觉。

## 4. 统一产品方向

### 4.1 核心体验目标

用户进入 Bombe 后应按以下路径理解内容：

1. 先知道自己位于哪个章节、当前目标是什么。
2. 先看到一个可观察的对象，再看到少量解释。
3. 每次交互只改变一个清晰变量：视角、拆解程度、轮位、接线、答案或剧情选择。
4. 页面始终告诉用户“现在发生了什么、下一步能做什么、为什么这个结果成立”。
5. 任何页面都能暂停、返回、重试和恢复，不因一次错误或设备性能问题中断学习。

### 4.2 视觉系统

建立 `bombe-ui` 视觉令牌，集中写入 `palette.css` 或新增 `tokens.css`：

- **颜色**：深蓝背景、暖白纸面、黄铜/铜色交互强调、墨黑正文、低饱和警示红；选中、完成、错误和禁用状态必须有独立对比。
- **字体**：标题保持展馆感，正文使用稳定的中文无衬线；数字、编号、轮位和时间使用等宽字体；不在单个页面临时改变字重和字距。
- **表面**：纸张卡片、玻璃标记、金属控制台和三维场景使用同一套边框、阴影、圆角和噪声规则。
- **间距**：以 8px 为基础单位，桌面使用固定安全区，手机使用连续纵向流；不再用页面特有的负边距解决核心内容布局。
- **状态色**：`idle`、`hover`、`active`、`selected`、`progress`、`success`、`error`、`disabled` 全部定义 CSS 变量。
- **控件语义**：主要动作只有一个高亮按钮；次要动作使用文字/线框；危险或重置动作不与完成动作使用相同视觉权重。

### 4.3 共享信息层级

所有页面共享以下层级：

1. 章节编号与标题。
2. 当前页面目标或教学问题。
3. 三维对象/实验对象。
4. 当前状态、反馈和下一步。
5. 详细解释、来源和高级设置。

设置、帮助、来源、历史细节和高级诊断默认进入弹层或可折叠区域，避免盖住核心模型和任务。

## 5. 目标架构与事件契约

### 5.1 建议的共享模块

在不一次性重写全部项目的前提下，逐步增加以下模块：

```text
src/
├── app-state.js             # 页面、选择、任务、偏好、弹层的唯一状态
├── events.js                # 事件名称、载荷和订阅工具
├── page-shell.js            # 共享导航、章节标题、状态条、焦点管理
├── transitions.js            # 可逆页面/弹层/场景转场
├── audio-feedback.js         # 非阻塞音频反馈和音量偏好
├── quality.js                # 画质分档、像素上限和 reduced-motion
├── resource-scope.js         # Three.js 资源注册与释放
├── ui/                      # 可复用 DOM 控件和状态反馈
└── pages/
    ├── history-page.js
    ├── exhibit-page.js
    ├── lab-page.js
    ├── challenge-page.js
    └── mission-page.js
```

已有模块可先通过适配层接入，不要求首轮迁移所有文件名。每次页面改良后再删除重复实现。

### 5.2 页面状态最小模型

```js
{
  route: { page, topic },
  transition: { phase, progress, interrupted },
  selection: { recordId, partId, lane, row },
  exhibit: { explode, running, camera, focus },
  lab: { prepared, step, rotorPositions, wiring, trace, history },
  challenge: { seed, level, phase, hints, attempts, completed },
  mission: { beat, location, evidence, choices, paused },
  preferences: { quality, motion, sound, music, theme },
  overlay: { type, previousFocus }
}
```

渲染层不得从 DOM 文本反推任务状态；题目、实验记录和证据记录必须有可测试的数据源。

## 6. 共享壳层改良计划

### 6.1 导航和章节识别

- 保留 00–04 五章入口，但让当前章节同时显示编号、短标题和一句任务说明。
- 顶部导航在窄屏收为可展开章节目录，当前章节进入后自动聚焦标题。
- 页面切换时显示“正在进入哪一章、准备了哪些资源、是否可以跳过”，资源失败时提供重试和返回入口。
- 章节内部的二级入口（实验室鼓轮/接线、历史锚点、任务节拍）使用统一的 `aria-current`、焦点和滚动定位。
- 访客指南、结构笔记、设置和来源弹层使用同一套关闭、Esc、点击遮罩和焦点恢复逻辑。

### 6.2 加载、错误、空状态

- 加载阶段分成“读取内容、准备模型、预热材质、准备交互”四个可解释阶段。
- WebGL 失败时显示 2D 展示图、关键结构说明、文本目录和返回/重试按钮。
- 单个模型、音频或字体失败时保留页面主体，不让局部资源阻塞整个路由。
- 题目或任务数据异常时显示可重试的恢复状态，并保留已完成的本地进度。
- 所有错误状态都提供用户可理解的中文说明，同时保留开发诊断信息到 `console` 或诊断接口。

### 6.3 动效、声音和偏好

- 设置中统一提供：画质高/标准/性能优先，动效完整/减少，声音和音乐独立开关。
- 动效减少时，页面转场、拆解、相机复位、数据流和数字滚动直接或短时到位；教学步骤和反馈不隐藏。
- 音效只表达界面事件，不将历史事实或任务结果绑定到音频是否成功。
- 所有偏好保存到本地，首次进入遵循系统 `prefers-reduced-motion`。

## 7. 分页面改良任务

### 7.1 00 战时序章：从“长篇首页”变成“证据导览”

目标：让 18 节历史内容既有沉浸感，又不会让用户迷失在长页面中。

任务：

- 将首页首屏收敛成“时间范围 + 当前历史问题 + 开始阅读/进入展品”三项核心动作。
- 侧边目录显示章节编号、标题、时间标签和当前阅读进度；手机改为顶部可折叠目录。
- 每一节使用统一结构：事实摘要、关键人物/设备、证据或来源、下一节入口。
- 将历史叙述中的“已知事实”“页面重建解释”“仍有不确定性”明确区分，避免教学文案与史料混在一起。
- 对人物肖像、教学示意和场景卡片统一处理加载、替代文本、错误占位和减少动效。
- 章节滚动进入时只触发必要场景动画；离开视口的复杂场景暂停或降低帧率。
- 末尾增加三个清晰入口：看整机、做信号实验、进入连续任务；不让用户只依赖顶部导航。

验收重点：桌面长页定位、手机目录、键盘跳转、来源链接、减少动效、滚动后资源释放。

### 7.2 01 机械全貌：从“功能齐全”变成“逐层理解”

目标：用户在 30 秒内理解整机由哪些系统构成，并能安全地从总览进入单个部件。

任务：

- 首次进入用短入场解释“整机 → 部件 → 拆解”的关系；支持跳过并保留最终状态。
- 将主视区拆成三个视觉层：模型、当前观察标记、下一步提示；标记不与模型细节争夺对比。
- 结构目录、模型拾取和结构笔记使用同一份部件数据，保持编号、颜色、标题、热点和说明一致。
- 拆解滑杆、拆解按钮、视角按钮、运转按钮采用统一状态反馈；滑杆显示当前阶段名称，而不只显示百分比。
- 相机正面/斜视/背面/总览使用可中断的球面缓动；从部件特写返回时保留用户最后视角和拆解进度。
- 结构笔记先给“组成/观察/系统关系”三段短内容，再提供展开说明和史料入口。
- WebGL 失败时保留部件目录和结构笔记；模型不可用不能使页面成为空白。
- 资源生命周期接入统一 `resource-scope`，页面切换和返回后无重复渲染循环。

验收重点：整机、五部件、拆解中途反向、模型拾取、弹层焦点、手机构图、低质量模式和释放检查。

### 7.3 02 信号实验室：从“功能实验台”变成“可跟做的推理课”

目标：用户明确知道每一步输入什么、观察哪一段信号、结果如何证明当前概念。

任务：

- 鼓轮与接线拆成清晰的二级导航，但共享实验状态、记录和帮助。
- 实验台顶部固定显示：当前问题、实验准备状态、当前步骤、完成条件。
- 继续保留五步教学，但将每一步拆成“操作、观察、原因、完成反馈”四个区块；自由探索仍可随时切换。
- 鼓轮页使用一条高对比的信号路径，当前段、经过段和未经过段有稳定颜色语义；暂停后保留路径和轮位。
- 接线页先用一对可见端点表达连接关系，再显示完整接线板；错误连接给出可恢复提示，不直接重置用户工作。
- 键盘、按钮、方向键和触摸输入共享同一命令函数；输入设备改变时只更新提示文案。
- 记录面板显示输入、输出、轮位、接线和验证结论，支持复制或清除，但不覆盖实验主模型。
- 低画质模式降低粒子、光效和线宽，不移除信号方向、轮位和结果文字。
- 实验重置只重置实验状态，不重置全站偏好和章节进度。

验收重点：九段信号连续性、暂停/重播、换线互易、错误恢复、步骤完成、键盘/触摸、低画质和无 WebGL 文本替代。

### 7.4 03 解密挑战：从“六关集合”变成“有证据的学习任务”

目标：每一关都让用户知道当前要解决的子问题，并能从提示理解答案而不是盲猜。

任务：

- 将六关状态统一为 `intro → observe → act → verify → explain → next`，每个阶段只有一个主动作。
- 任务卡固定显示：目标、已完成条件、当前输入、提示级别、重试和查看解释。
- 提示分为两级：先缩小观察范围，再解释原理；使用提示不会扣除不可逆的进度。
- 观察台提供模型、键盘/输入、信号或答案区域的明确焦点边框；当前操作区与其他区域形成层级差。
- 答案反馈同时更新视觉状态、文字解释和证据记录；失败时保留用户输入和模型状态。
- 最后一关把轮位、接线、密文输入和三字母结果拆成四个可验证小步骤，避免一次性大表单。
- 题目种子、题目答案和完成进度只由 `challenge-engine` 管理；UI 不直接拼装正确答案。
- 重新抽题前明确告知会生成新种子，并保留已完成徽章/历史记录的策略。
- 手机先显示任务和当前输入，再显示模型；桌面使用模型、任务卡、记录三栏。

验收重点：六关可重试、防跳关、随机题唯一性、最终解密、提示路径、键盘焦点、手机纵向布局和刷新恢复策略。

### 7.5 04「黎明之前」：从“连续场景”变成“可暂停的证据链”

目标：让 15 个节拍形成一条可理解的推理链，而不是只观看一段长场景。

任务：

- 场景顶部或侧边显示当前位置、当前证据目标和已确认线索；不显示内部节拍编号作为用户任务文本。
- 每个节拍进入后先给一个可读的现场目标，再开放交互对象；完成后留下证据卡和简短解释。
- 七个区域使用统一的空间标识和颜色辅助，但不依赖颜色单独表达状态。
- 过场可跳过、可暂停、Esc 可继续；中断后从当前场景和当前证据状态恢复。
- 资源选择、角色选择、风险判断和最终交接均使用统一的确认、取消、重试和结果反馈模式。
- 将无线电、截收纸、档案、关系图、Enigma、Bombe、地图和交接物件注册为可访问对象，提供键盘路径和文本描述。
- 连续任务中的算法结果与视觉动画分离：计算先完成并写入状态，动画只负责表达过程。
- 任务完成后提供证据链回顾、关键判断和返回章节入口；刷新是否重开要在页面内明确说明。
- 低画质/减少动效时保留场景空间关系与关键对象，减少镜头移动、粒子和环境细节。

验收重点：15 节拍顺序、暂停/隐藏页、过场跳过、证据记录、任务失败恢复、键盘导航、低性能设备和刷新行为。

## 8. 数据、内容与教学一致性

- 00 页历史内容继续由数据文件驱动，章节、时间、人物、来源和状态不写死在场景代码中。
- 01 页部件数据同时提供模型 ID、标题、编号、颜色、热点、笔记、观察步骤和实验入口。
- 02 页实验数据同时提供轮位、接线、路径、记录和判定，所有结果由 `cipher.js` 计算。
- 03 页题目由可复现种子生成；题干、选项、正确条件、提示和解释保持同一题目对象。
- 04 页节拍由任务数据和场景状态驱动；证据记录引用稳定 ID，不依赖 DOM 文本。
- 文案编辑必须同时检查中文、英文标签、屏幕阅读器文本、移动端换行和键盘提示。
- 史料来源与教学重建说明分开呈现；程序化模型继续明确标注“教学性三维重建”，不暗示可制造精度。

## 9. 性能、可访问性与降级标准

### 9.1 性能

- 设定渲染比例、像素密度、阴影、AO、后处理和粒子上限；默认标准档，性能优先不改变教学逻辑。
- 重复结构使用实例化；独立拾取对象保留稳定 ID。
- 页面隐藏、弹层打开、任务暂停和静止状态降低帧率；离开页面立即停止旧场景循环。
- 统一资源注册表保证几何、材质、纹理、RenderTarget、后处理和事件监听器可释放。
- 记录每页首次进入准备时间、稳定帧率、绘制调用、三角形、纹理数量和释放后残留。

### 9.2 可访问性

- 所有页面有唯一主标题、章节地标、跳过链接和可读的当前状态。
- 模型画布必须有可操作说明和文本替代；关键结构不能只通过 3D 视觉表达。
- 交互控件支持键盘、触摸和鼠标；焦点可见，弹层焦点不泄漏到背景。
- 颜色不是唯一状态通道；完成、错误、选中和禁用同时使用文字、图标或形状。
- 遵守 `prefers-reduced-motion`，并为自动镜头、转场、数据流、滚动数字和声音提供独立的可控行为。
